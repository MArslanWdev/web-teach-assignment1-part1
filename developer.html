Introduction

The Paywise API helps your application create payments, manage customers, and track transactions. Requests use standard HTTP methods and return data in JSON format.

You can try the API in a test environment before accepting real payments. Test requests do not move money.

Authentication

Each API request must include a secret key. Keep secret keys on your server and never share them in public code or web pages.

Just getting started?

Follow our quickstart guide to make your first test request.

Not a developer?

You can also create payment links and manage invoices from your Paywise dashboard without writing code.

Errors

Paywise uses HTTP status codes to show whether a request worked or needs attention. These code ranges are a useful first guide:

  • 2xx means the request completed successfully.
  • 4xx means the request needs to be checked. This can happen when information is missing or an account does not have permission.
    • Check the error message for details about the problem.
    • See error handling for tips on what to do next.
  • 5xx means something went wrong while Paywise was processing the request. Try again later.

If a request fails, check its status and message before trying it again.

HTTP status code summary
200 OK The request was completed.
400 Bad Request Some request information is missing or invalid.
401 Unauthorized A valid API key was not provided.
403 Forbidden Your account cannot perform this action.
404 Not Found The requested item could not be found.
409 Conflict The request conflicts with the current item state.
424 Dependency Failed A service needed to finish the request is unavailable.
429 Too Many Requests Wait briefly before sending more requests.
500 Server Error Paywise could not complete the request right now.
